# UiPath GenAI and Integration Service

Treat AI as a probabilistic subsystem inside a deterministic RPA shell. Keep routing, retries, validation, audit, and business-rule enforcement deterministic; use AI only where semantic judgment or adaptive UI interaction earns its uncertainty and unit consumption.

## 1. Establish the real execution context

1. Invoke `uipath-rpa` and follow its project discovery and host-aware validation process.
2. Read the nearest `project.json`, the relevant workflow, a working sibling, and installed package versions before choosing or serializing an activity.
3. Identify the branch explicitly:
   - **GenAI Activity**: UiPath-managed models through the UiPath GenAI Activities connector.
   - **ScreenPlay**: agentic UI interaction from the UI Automation package.
   - **Integration Service**: connector activity, HTTP activity, or event trigger for an external system.
   - **Hybrid**: more than one branch; draw the execution boundary and meter each branch separately.
4. Confirm Automation Cloud region, Studio/Robot version, target framework, folder, connection ownership, license plan, data sensitivity, and whether a signed-in Windows authoring/runtime environment is available.

Completion criterion: the branch, package/activity source of truth, runtime host, connection boundary, data classification, and license plan are known or recorded as explicit blockers.

## 2. Choose the narrowest capable activity

Read [genai-activities.md](references/genai-activities.md) for GenAI selection and configuration. Prefer a task-specific activity when its typed inputs and outputs match the job; use Content Generation when custom instructions, model selection, or Context Grounding are essential.

Read [screenplay.md](references/screenplay.md) whenever ScreenPlay is proposed or present. Use it for controlled agency at unstable or semantically difficult UI steps, not as an automatic replacement for stable selectors, APIs, or deterministic logic.

For ordinary connectors, read [integration-service.md](references/integration-service.md), then follow the matching `uipath-rpa` Integration Service reference in full. Prefer API-level connector activities over UI automation when the external system exposes the required operation.

Completion criterion: the selected activity has a documented capability match, compatibility match, connection path, output contract, and a stated reason it is preferable to a deterministic alternative.

## 3. Design the contract before the activity

Define:

- bounded input and redaction path;
- prompt/task text with dynamic data separated from instructions;
- typed output or a strict parseable schema;
- deterministic validation rules and confidence/fallback thresholds;
- retryable versus terminal failures;
- human-review conditions;
- idempotency key and side-effect boundary;
- telemetry that records activity, outcome, latency, model/tier when exposed, and unit-driving counts without prompts, model responses, secrets, or sensitive data.

For GenAI outputs, validate structure, allowed values, required evidence, and business invariants before any irreversible action. Route invalid, ambiguous, low-confidence, or safety-sensitive results to deterministic fallback or Action Center review.

For side-effecting Integration Service calls, complete AI inference and validation first, then execute the external write once. Use a lookup/idempotency check before retries.

Completion criterion: every probabilistic output and external side effect has an observable success condition, bounded failure route, and replay-safe behavior.

## 4. Build from generated metadata, not memory

Use Studio-generated XAML, installed package documentation, or `uip rpa activities get-default-xaml` in a signed-in supported environment. Copy activity tags, namespaces, configuration blobs, field objects, enum values, and output types from that source of truth.

For Integration Service activities, resolve the live connector, connection, operation/object, criteria-gated fields, and schema. Preserve generated configuration and every returned field object. Bind secrets through connections or credential assets and keep connection identifiers deployable through folder/solution bindings.

For ScreenPlay, preserve the containing Use Application/Browser scope and the activity shape generated by the installed UI Automation package. For GenAI connector activities, preserve the generated Integration Service binding and connection metadata.

On an unsupported or unsigned Mac host, perform only the static work allowed by `uipath-rpa`; leave exact Designer-generated activity serialization unresolved when no trusted sibling or package metadata exists. State that Windows Studio/Robot validation remains required.

Completion criterion: no activity class, property, connector field, configuration blob, model enum, or binding was guessed.

## 5. Run a unit-budget review before execution

Read [pricing-governance.md](references/pricing-governance.md) in full. Recheck the linked official pricing pages because rates, entitlements, and meters can change.

Calculate expected executions from business volume, retries, development tests, evaluation runs, ScreenPlay UI-action bands, and Integration Service calls. Show low/base/high scenarios and identify which assumptions come from the tenant's actual plan versus public documentation.

Add spend controls appropriate to risk: deterministic prefilters, cache/reuse, maximum retries, ScreenPlay maximum steps, sample-based evaluation, tenant allocation/notification monitoring, and a kill switch. Do not execute a paid activity merely to discover its schema or test plumbing when a generated default, mock, or saved fixture can answer the question.

Completion criterion: the user can see the unit-driving count, rate source and date, low/base/high estimate, spend guardrails, and any unresolved contract ambiguity before a costly or high-volume run.

## 6. Validate behavior in layers

1. **Static**: project dependency, XAML/JSON integrity, sidecars, bindings, connection references, secret handling, invoke contracts, and `uipath-rpa` checks.
2. **Contract**: saved fixtures for normal, malformed, empty, adversarial, long, multilingual, and sensitive inputs; schema and invariant assertions.
3. **Evaluation**: representative labeled cases with acceptance thresholds for accuracy, abstention, false-positive/false-negative costs, latency, and per-case activity counts.
4. **Integration**: non-production connection/folder, reversible external operations, retry/idempotency proof, and permission failure tests.
5. **Runtime**: signed-in Windows Studio/Robot compile and run; inspect ScreenPlay traces or GenAI outputs without copying sensitive content into logs.
6. **Production gate**: human review for consequential decisions until the evaluation and monitoring evidence supports narrower automation.

Completion criterion: report exactly which layers passed, the evidence produced, observed activity/run counts, and every remaining production blocker.

## Delivery

Report:

- selected branch and activities;
- packages, connections, bindings, and workflow files changed;
- prompt/task and output-contract locations;
- deterministic fallback and human-review routes;
- unit estimate and safeguards;
- validation performed and Windows/runtime work still outstanding;
- official documentation pages rechecked and their verification date.
